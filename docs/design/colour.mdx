Every colour in the dashboard is a CSS variable defined in <Source path="src/app/tokens.css" />, once for light mode and once for dark. Components never use a raw colour; they use the variable's name through Tailwind, like `bg-card` or `text-muted-foreground`. Change a value in that file and every screen follows.

The values are written in [OKLCH](/reference/glossary#oklch), a colour format where lightness means what it looks like it means. That makes it easy to build a dark theme with the same contrast as the light one. The hex codes below are close equivalents, for reference.

## The orange

One orange, in two strengths, with two soft companions.

<Why>
  Orange 500 is the brand colour, but white text on it fails contrast, and orange text on white is worse. So buttons use a deeper orange 600 that white text reads clearly on, and the brighter 500 is kept for things that aren't words: bars, progress, the focus ring.
</Why>

## State tones

Five tones carry every status in the app. Each has a soft background (`-subtle`), a text colour (`-text`), and a solid for dots and icons. Components don't pick a colour for a status themselves: <Source path="src/lib/orders.ts" /> and <Source path="src/lib/reservations.ts" /> map each status to a tone and an icon in one place.

## Using the tokens

Tailwind turns each variable into classes, through the `@theme inline` block in <Source path="src/app/globals.css" />:

```tsx
<div className="rounded-xl bg-card p-6 shadow-md">
  <p className="text-sm text-muted-foreground">Today's sales</p>
  <span className="rounded-full bg-tone-green-subtle px-2.5 text-tone-green-text">Ready</span>
</div>
```

Dark mode needs nothing extra in components: the `.dark` class on `<html>` swaps the variables underneath.

<Note>
  Adding a new colour is a design decision, not a coding one. If a screen seems to need one, it's usually a sign that one of the three jobs (action, data, state) is being stretched.
</Note>
